# MarkGleam 发布质量审计

审计日期：2026-07-30

审计范围：`main` 分支正式发布前的功能、兼容性、视觉、交互、性能、可访问性与工程质量

结论：计划内核心路径全部通过，未发现遗留的 P0、P1 或 P2 缺陷；可以进入发布前人工验收。

## 1. 验收口径

本轮以“覆盖已定义的用户路径且不存在已知高优先级缺陷”为完成标准，不使用无法证伪的“保证绝对没有 Bug”。缺陷分级如下：

- P0：产品不可用、数据损坏或核心导出完全失败。
- P1：常见场景的核心功能失败，或移动端主路径无法完成。
- P2：有规避方式但会明显影响功能、兼容性、交互或性能。
- P3：轻微视觉、文案和一致性问题。

## 4. 本轮新发现与修复

- 背景颜色此前只保存设置，没有作用于预览和导出；现已打通，并为旧设置增加迁移。
- Terminal 主题的明暗切换名称与行为不一致；现按实际状态显示和切换。
- 同时导入多张图片时使用旧 Markdown 快照，前面的图片会被覆盖；现支持真正的多选与顺序追加。
- 多图导入逐张触发预览时，Firefox 并发环境可能在首张图解码前释放 Blob URL；现先完成全部资源写入，再一次性提交 Markdown，连续 12 轮专项回归和完整三浏览器矩阵均通过。
- 导入文件、IndexedDB、本地图片和字体保存失败时缺少反馈；现提供可恢复的错误提示。
- Blob URL、背景图和自定义字体存在异步竞态及资源释放遗漏；现统一等待资源就绪并在安全时机释放。
- 透明背景仍会输出背景图；现明确忽略背景图并禁用冲突设置。
- 连续强制分页符可能产生 PDF/ZIP 空页，空内容分片导出可能失败；现均输出稳定结果并有单元测试。
- `---` 恢复为标准 Markdown 水平分隔线；强制分页改用独立一行的 `<!-- pagebreak -->`，避免题库和文章被意外拆成大量稀疏页面。
- 超长文档 PDF 不再为每一页克隆整篇 DOM；现仅复制当前页内容，提供逐页进度与取消，并默认压缩 100 页以上的栅格页面。分页按浏览器实际折叠后的块间距计算，页面背景会铺满纸张可用区域，剩余留白只来自不可拆分内容块、文档结尾或显式分页。
- 默认示例末尾的分页符造成一句正文独占第三页；已移除，默认 PDF 现在为两页。
- 通用字段组件的标签包住多个交互控件，导致辅助技术读出错误名称；已按单控件标签或控件组重构。
- 对话框和弹出菜单缺少完整键盘语义；现支持唯一标题、焦点陷阱、Escape、点外关闭和焦点恢复。
- E2E 原本可能复用端口上无关服务而产生假通过；现使用独占端口 `4327`、严格端口和禁止复用。
- GitHub Pages 工作流此前没有浏览器回归门禁；现于部署前运行 Chromium E2E。
- CodeMirror 主题包装层使用 `.cm-theme-light/.cm-theme-dark`，但样式误写为不存在的 `.cm-theme`，导致编辑器按全文高度撑开后被外层裁剪；现改用稳定的组件类名约束完整高度链路，桌面滚轮回归已在 Chromium、Firefox、WebKit 通过。
- 桌面编辑器懒加载时曾先展示一个可输入的临时 `textarea`，随后替换为 CodeMirror，Firefox 下会造成元素卸载、焦点丢失和输入中断；现加载阶段只显示不可编辑状态，CodeMirror 挂载后才暴露带稳定可访问名称的文本框。Firefox 专项连续 10 轮和完整三浏览器矩阵均通过。
- 全格式导出矩阵并发占用较高，Playwright 使用全部逻辑核心时可能直接压垮 Firefox 页面进程；本地并发固定为 4，CI 固定为 2，避免把资源耗尽误报为产品失败。
- 顶部太阳/月亮按钮原先直接切换“暖纸/夜航”内容主题，与右侧主题面板重复且不符合图标语义；现将应用外观与导出主题拆为独立状态，顶部按钮只改变工作台和编辑器，预览与导出保持用户选择的内容主题。
- 免费导出署名曾可被自定义 CSS 通过高层级正文或伪元素间接盖住；现把正文锁定在低层叠上下文，并用 `elementFromPoint` 回归验证署名仍位于可见最上层。
- 署名原先用固定亮度阈值选择黑白文字，中灰背景可能对比不足；现比较两套前景色的实际对比度，并在余量不足时自动增加局部对比底板。

## 5. 产品与设计决策

### 移动端保留轻量编辑器

桌面端继续使用 CodeMirror，移动端使用原生 `textarea`。对照 `wx-publisher` 的相同取舍后，移动端的首要目标是触摸滚动、输入法和光标行为稳定；语法高亮的收益不足以抵消重型编辑器在窄屏上的负担。移动端仍保留完整 Markdown 编辑与实时预览能力。

### 桌面端保留 CodeMirror

桌面端原生 `textarea` 虽然更轻，但会损失行号、折叠、搜索、括号匹配和 Markdown 语法编辑体验。Monaco 是 VS Code 的核心编辑器，适合多语言 IDE，但其 Worker、加载体积和集成复杂度对本产品明显过剩。CodeMirror 已经提供所需能力且按桌面路径懒加载，本次问题仅是包装层高度选择器错误，因此保留 CodeMirror 并修复滚动约束是收益、风险和维护成本最平衡的方案。

### 应用外观与导出主题分离

顶部太阳/月亮图标按通用产品心智控制整个应用的浅色/深色界面，并让 CodeMirror 跟随界面外观。右侧主题卡片只决定 Markdown 预览和导出结果。两项分别持久化，互不覆盖；因此用户可以在深色工作台中继续导出“暖纸”，也可以在浅色工作台中导出“夜航”。

### 语言提供中英日三个等价版本

工具面向公开访问，默认不假设用户来自特定市场：未主动选择时按浏览器语言展示中文、英文或日文，其他语言回退到英文；用户主动选择后才保存偏好。三个版本使用等价路由、完整词条和互相可见的语言入口，并纳入持久化回归。

原生 `select` 的弹层由操作系统和浏览器绘制，暗色模式下无法可靠匹配工作台配色，因此语言选择改为项目内的轻量可访问菜单。它保留 `listbox/option` 语义、方向键、Escape、点击外部关闭和焦点恢复。曾评估 Radix Select，但仅两个选项就会增加约 30 kB gzip 的首屏脚本并引入近 40 个传递依赖，收益不足以覆盖性能与维护成本；当前不引入整套 UI 组件库。

### 导出完成状态按参数失效

“导出完成”只表示当前内容与当前导出参数已经成功。内容、格式、清晰度或 PDF 设置变化后立即恢复为普通下载状态，避免用户误以为新配置已经导出。

### 不为包体告警进行高风险拆分

编辑器、导出和 Mermaid 已按使用路径异步加载。现有大块主要来自 CodeMirror、Mermaid、html2canvas 和 jsPDF；仅为消除构建告警继续手工拆包，收益有限且会增加加载竞态风险，因此本轮不做。

## 6. 性能与视觉结果

- 基线主包：408.85 kB，gzip 129.61 kB。
- 当前主包：454.71 kB，gzip 145.87 kB；增加的逻辑覆盖统一工作台、多输入模式、SEO 路由、品牌署名、错误恢复、状态迁移与可访问性。
- 重依赖保持按路径加载：导出模块 gzip 168.58 kB、桌面编辑器 gzip 212.51 kB、Mermaid 核心 gzip 138.18 kB，不阻塞未使用这些能力的首屏路径。
- 生产构建、本地暖缓存、120 行文档的实验数据：DOMContentLoaded 约 28.5 ms，First Meaningful Paint 约 94.9 ms，任务总时长约 154.9 ms，已用 JS 堆约 14.5 MB。该数据用于本轮相对比较，不代表公网设备 SLA。
- 默认 PDF 经 `pdfinfo` 验证为 2 页 A4、459,559 B，并以 Poppler 渲染两页检查；无黑页、空白尾页或内容损坏。
- 上传图片 PDF 经 Poppler 渲染检查为 1 页 A4、37,775 B；本地图片、背景和正文均正常。

## 7. 剩余风险与未覆盖范围

- 尚未在真实 iPhone/iPad Safari 和 Android Chrome 设备上执行；当前移动结论来自 390×844 模拟视口及 WebKit/Chromium 引擎。
- 剪贴板写入依赖 HTTPS、浏览器实现和用户权限，自动化主要验证能力存在时的写入及不支持时的下载回退。
- 远程图片是否可直接导出仍受图片源站 CORS 控制；产品已提供失败占位与可执行建议，下载后作为本地图片导入最可靠。
- Firefox/WebKit 未重复执行全部高成本格式矩阵；核心 PNG/PDF 和移动路径已覆盖，完整全格式矩阵由 Chromium 与 CI 守护。
- 构建仍提示部分异步 chunk 超过 500 kB；它不影响正确性，后续只有在真实网络性能数据表明需要时再优化。

当前没有已知 P0、P1 或 P2 遗留项。以上风险均属于环境覆盖或后续性能观察项，不阻断本次发布。

### 原生打印与更新日志（2026-07-30）

- 新增独立的“打印 / 可搜索 PDF”选项，使用浏览器原生文字 PDF；默认白底、11pt 正文，可选择保留主题背景。
- A4/Letter、方向、页边距、表格重复表头和 `<!-- pagebreak -->` 已纳入 Chromium 端到端回归。
- 904 KB 原始题库打印基准为 303 页、5.1 MB，生成约 11.2 秒；首、中、末页均可提取文字且无裁切或重叠。
- 保留中英日三语 `#/changelog` 页面，使用 hash 路由兼容 GitHub Pages 静态部署；更新日志不占用主帮助菜单，可通过直接链接分享。
